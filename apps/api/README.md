# Fineline API (`apps/api`)

The HTTP API of Fineline: the public shop (photo upload and drawing preview, frames, orders) and the
admin tool (login, orders, frames, settings). TypeScript on Node 22, Fastify 5, Zod, Drizzle ORM on
PostgreSQL 16, Vitest. The contract is [`docs/api/openapi.yaml`](../../docs/api/openapi.yaml); the
conversion worker it calls is described in [`docs/api/worker-openapi.yaml`](../../docs/api/worker-openapi.yaml).

## Quick start

Needs Node 22.12+ (`nvm use` reads the repo's `.nvmrc`) and a PostgreSQL 16 with two databases, one
for the app and one for tests (the test database is wiped on every test run).

```sh
cd apps/api
npm ci
cp .env.example .env
# Fill in the two secrets in .env:
openssl rand -base64 32               # -> WORKER_TOKEN (same value as the worker's)
npm run hash-password                 # type the admin password (12+ characters) -> ADMIN_PASSWORD_HASH
# For plain http://localhost also set COOKIE_SECURE=false.

npm run db:migrate                    # apply the SQL migrations to DATABASE_URL
npm run dev                           # http://localhost:3000/api/v1/health
```

With the repo's compose dev override the database runs in Docker on `127.0.0.1:5432`; any local
PostgreSQL works too:

```sh
createuser fineline -P               # password used in DATABASE_URL / TEST_DATABASE_URL
createdb -O fineline fineline
createdb -O fineline fineline_test
```

The worker (`apps/worker`) must run at `WORKER_URL` for uploads to work; everything else works
without it. Uploads answer `503 conversion_unavailable` while it is down.

## Configuration

Every variable is documented in [`.env.example`](.env.example) and validated once at startup
(`src/config.ts`); the API refuses to start and names the variable when one is missing or invalid.
The secret placeholders in `.env.example` fail validation on purpose (SR-020). Behind nginx set
`TRUST_PROXY=1` so rate limits see the real client address and a client-set `X-Forwarded-For` is
ignored (nginx overwrites it, SR-017).

## Layout

```
src/
  app.ts            buildApp(deps): plugins, hooks, routes (no listen; tests use inject)
  server.ts         config -> database -> storage -> worker client -> listen; retention timer; shutdown
  config.ts         Zod schema for the environment
  domain/           pure business rules, no HTTP or SQL: working days (Europe/Amsterdam), order
                    numbers, status machine, SVG drawing check, image type and metadata, retention
  modules/<area>/   *.routes.ts (HTTP only) -> *.service.ts (use cases, transactions)
                    -> *.repository.ts (Drizzle queries)
    admin/          the one admin plugin (auth + CSRF hooks), login/logout, sessions
    drawings/       POST /drawings, preview tokens
    frames/         public catalogue and admin frames
    orders/         POST /orders and the admin order routes
    settings/       lead time
    retention/      the retention sweep
  storage/          FileStorage interface + local disk implementation
  worker/           worker HTTP client and the conversion concurrency limit
  lib/              errors, error handler, multipart limits, rate limits, logger, validation
  db/               schema, client, migrations/ (generated by drizzle-kit, committed)
  scripts/          migrate.ts, hash-password.ts, erase-order.ts
tests/              HTTP tests; helpers/ (harness, contract check, worker stub, fixtures)
```

To add an endpoint, copy the pattern of `frames`: a Zod schema in `*.schemas.ts`, a service
function, repository queries, a thin route. Admin routes go into the admin plugin's `routes` list in
`app.ts`, which puts them behind authentication and the CSRF check automatically.

## Conventions

- **Errors**: services throw `AppError` (`src/lib/errors.ts`); one handler sends
  `{ "error": { "code", "message", "details"? } }`. Unknown errors become a generic 500 and are logged
  without their message (pg and Drizzle messages contain values). Validation `details` name the field,
  never the input.
- **Input**: every body, query, path parameter, multipart field and env var goes through Zod with
  unknown fields refused. Malformed UUIDs in paths answer 404 before any query.
- **Time**: business code takes a `Clock`; tests inject one. Calendar dates are Europe/Amsterdam.
- **Money** in integer cents, lengths in mm, IDs UUIDs, timestamps ISO 8601 UTC.
- **Logs**: pino with redaction; no customer data, file names, passwords, tokens or session IDs.
  Client addresses only in security events (`login_failed`, `rate_limited`, `csrf_failed`, ...).
- **Tests** name the acceptance criteria they cover (`it("AC-020 ...")`). Every HTTP test response is
  checked against `docs/api/openapi.yaml` by `tests/helpers/contract.ts`, so contract drift fails the
  build. HTTP tests use a stub worker (`tests/helpers/worker-stub.ts`), never the Python worker.

## Testing

`npm test` needs `TEST_DATABASE_URL` (from `.env` or the environment) pointing at a database whose
name contains `test`. A Vitest global setup drops and recreates its schema and applies the
migrations; test files run one at a time and reset the tables before each test. CI uses a
`postgres:16` service container.

| SR-004 bounded conversions                            | `worker/worker-client.ts` (`ConversionLimiter`)                                                                      |

| SR-010 to SR-014 admin auth, sessions, CSRF, one gate | `lib/password-hash.ts`, `modules/admin/` (login attempts counted before scrypt, one scrypt at a time)                |

## Erasing a customer's data on request

For a GDPR erasure request (SR-022, Q-24), with `DATABASE_URL` and `STORAGE_DIR` set (from `.env`):

```sh
npm run erase-order -- FL-2026-0042
# in the container:
docker compose exec api node dist/scripts/erase-order.js FL-2026-0042
```

It deletes the order's photo and drawing files, then replaces the customer's name, email, street,
house number, postal code and city with `[erased]`. It keeps the order number, price, dates, status,
frame and country for the books. Running it again is safe ("already erased"). It prints only the
order number. Afterwards the admin tool shows the order without a photo (410) or drawing (404
`drawing_deleted`). Backups still hold the data until they expire (hosting, manual check).

## Docker

`Dockerfile`: multi-stage on `node:22.22-slim`, production dependencies only, runs as the
unprivileged `node` user, applies migrations and then starts. Mount a volume at `/data/storage`
(`STORAGE_DIR`). Generate the admin hash with
`docker compose run --rm api node dist/scripts/hash-password.js`.
